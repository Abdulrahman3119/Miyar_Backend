# خطة إغلاق فجوات معيار (بدون التكاملات)

**النطاق:** من ≈76% → ≈90% (Pilot)  
**خارج النطاق الآن:** SMS / بوابة دفع / نفاذ (مرحلة لاحقة)  
**المرجع:** `docs/BRD_v2_gap_analysis.md` + BRD v2.0 (B.R.112–239)

---

## المبادئ

1. **الصلاحيات أولاً** — لا نفتح مسارات وظيفية جديدة قبل توحيد مصدر الحقيقة.
2. **إنفاذ على السيرفر** — الواجهة تُخفي الأزرار؛ السيرفر هو الحكم.
3. **ملحق 7.1 = `miyar.ui.PERMISSION_MATRIX`** — مصدر وحيد للفرونت والـ API.
4. **كل تغيير صلاحيات يمر باختبار سلبي** (يجب أن يفشل).

---

## المرحلة A — صلاحيات وأمن API (أسبوعان) — Critical Path

| ID | المهمة | معيار الإغلاق | حالة |
| --- | --- | --- | --- |
| A1 | توثيق/تثبيت المصفوفة كمصدر حقيقة + `require_capability()` | كل write حساس يستدعي القدرة | ✅ |
| A2 | قفل الجهة الإشرافية (قراءة فقط) على كل write | Supervisor لا يمرّر أي mutating API | ✅ |
| A3 | فصل إخفاء/حذف التقييم (Support vs Admin) B.R.128 | STS07=support/admin ، STS08=admin فقط | ✅ |
| A4 | تدوير `api_secret` عند Logout | بعد الخروج التوكن القديم لا يعمل | ✅ |
| A5 | تقليل `ignore_permissions` غير الضروري + مراجعة `allow_guest` | قائمة مراجعة موثّقة | ✅ |
| A6 | إزالة `engine.run` من Supervisor في المصفوفة | مطابق BRD 3.2.1 | ✅ |
| A7 | سكربت اختبار صلاحيات حرجة (Permission Matrix) | ≥ 20 سيناريو حرج أخضر | ✅ (أساسي) |

**مخرجات المرحلة A:** `miyar.api.common.require_capability` + حماية `write`/`geotech`/`engine` + اختبارات.

## المرحلة C — صقل الجودة (أسبوعان، بعد A+B)

## ترتيب التنفيذ الفعلي (Sprint 1 — الآن)
