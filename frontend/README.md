# منصة معيار — واجهة النظام (React + Tailwind)

نموذج تشغيلي كامل للمنصة الوطنية لاختبارات التربة والطرق (الإدارة العامة لكود البناء السعودي — وزارة البلديات والإسكان)، من تسجيل الدخول حتى اعتماد تقرير الدراسة الجيوتقنية، مبني على BRD v2.0 ومصفوفة الصلاحيات، مع تصحيحات نتائج البحث في الكود السعودي (SBC 303/301) وضوابط NCA ECC-2:2024.

- **عربي فقط · وضع فاتح فقط · RTL** — لا يوجد وضع داكن ولا لغة ثانية.
- Vite 8 · React 19 · TypeScript · Tailwind 4 · Zustand · React Router 7 · Recharts · lucide-react
- يعمل بوضعين: **بيانات العرض** (`src/lib/mock.ts` + آلة الحالات في `src/lib/store.ts`) أو **مربوطاً بالخادم** (تطبيق Frappe اسمه `miyar`) عند ضبط عنوان الخادم.

## التشغيل

```bash
npm install
npm run dev        # http://localhost:5173
npm run build && npm run preview   # http://localhost:4173
```

## الربط بالخادم (Frappe / ERPNext)

عنوان الخادم يُضبط من **الإعدادات ← الاتصال بالخادم** (أو من رابط «تغيير» أسفل شاشة الدخول) ويُحفظ في `localStorage` لهذا المتصفح فقط. بدون عنوان يبقى كل شيء على بيانات العرض.

```bash
# في الـ bench: miyar مثبّت على site1، والخادم الافتراضي 8002 يخدم موقعاً آخر
bench --site site1 serve --port 8010
```

ثم ضع `http://localhost:8010` في حقل العنوان → «فحص الاتصال» → «حفظ وربط».

- الدخول برقم جوال مسجَّل في المنصة عبر OTP؛ في `developer_mode` الرمز `1234` ويُعرض في الحقل.
- أرقام العرض نفسها مبذورة في الخادم: `0551234567` مقاول (مفوّض رئيسي) · `0559876543` مختبر · `0553334444` استشاري · `0550001111` مدير نظام.
- المصادقة `Authorization: token api_key:api_secret` يُصدره `miyar.api.auth.verify_otp` ويُحفظ محلياً؛ «تسجيل الخروج» يُبطل الجلسة.
- المقروء من الخادم حالياً: الجلسة والمستخدمون، دليل المنشآت، الاختبارات المرجعية، كتالوج المختبرات، قواعد الأعمال، وطلبات الاختبارات. بقية الشاشات (الدراسات، العقود، الفواتير، الأدلة…) ما زالت على بيانات العرض وتُربط تباعاً.
- الملفات: `src/lib/backend.ts` (العميل والعنوان والتوكن) · `hydrate/loginLive/requestOtp` في `src/lib/store.ts` · `src/features/settings/BackendSettings.tsx`.
- نظير ذلك في الخادم: `miyar/api/auth.py` و`miyar/api/payload.py` (تحويل DocTypes إلى أنواع المتجر) و`miyar/api/session.py`.

## سيناريوهات جاهزة للعرض

1. **طلب قياسي كامل** — كمقاول: `/requests/new` → اختيار سريع من قائمة المختبر (قيد التصنيف) → 3 نطاقات → إرسال. كمختبر: `/requests/TST-2026-051` → النطاق الأول مختار افتراضياً → قبول (عدّاد 12 ساعة). ثم تنفيذ الاختبار: تسجيل استلام العينة (GPS) → المقاول يؤكد (يبدأ SLA) → إدخال النتائج مقابل الحدود المرجعية ورفع التقرير. كاستشاري: `/approvals` → مراجعة واعتماد/رفض (عدّاد 48 ساعة). رفض → المقاول ينشئ إعادة `TST-…-R1`.
2. **الدراسة الجيوتقنية الجارية** — `TST-2026-046` في المرحلة 3. كمختبر: خريطة الجسات → BH-02 قيد التنفيذ → إضافة طبقات (SPT يحسب N) وعينات → إكمال الجسة → Borehole Log مولّد (مع منحنى SPT-N).
3. **دراسة مكتملة ومعتمدة** — `TST-2026-038` في المرحلة 6: البيانات المعملية (9 عينات) → التحليل (حسابية/تحليلية زلزالية SBC 301/توصيات) → معاينة التقرير معتمدة وموزّعة → المستند في الأرشيف والنتائج.
4. **دراسة من الصفر** — كمقاول: طلب جديد بنوع "دراسة جيوتقنية" → البيانات الأولية (رفع القرار المساحي، استخراج، مساحة مبنية وأدوار) → كاستشاري: مراجعة → المحرك يقترح الجسات وفق **SBC 303 Table 2.1** → تعديل على الخريطة → اعتماد وإرسال للمختبر.
5. **الحوكمة** — كمدير نظام: `/admin/rules` (تعديل مهلة → حدث حرج في `/governance`) · `/admin/knowledge` (إصدارات القاعدة وأثرها) · `/governance` (الامتثال ECC، مصفوفة الصلاحيات).

## ملاحظات فنية

- الساعة مرجعها الوقت الفعلي (`Date.now()`) فتبقى العدّادات حيّة في العرض، والبذرة الثابتة تُبقي البيانات نفسها.

- **الصور في `public/evidence/` مأخوذة مؤقتاً من التقرير المرجعي في `References/` لأغراض العرض الداخلي — استبدلها بأصول العميل قبل أي عرض عام.**

## سيناريو العرض #1 — دورة اختبار قياسي كاملة في 5 دقائق

1. **المختبر** (`?as=u-lab`) → `/requests/TST-2026-049` — طلب مقبول وموعده المعتمد أمس → «بدء التنفيذ» → تسجيل استلام العينة (يُسجَّل بدء متأخر عن الموعد ويُخصم من الالتزام — B.R.149).
2. **المقاول** (`?as=u-cont`) → نفس الطلب → «تأكيد استلام العينة» (يبدأ عداد SLA، ويُسجَّل `confirmedAt`).
3. **المختبر** → إدخال النتائج والأبعاد والمعدات المعايرة والصور → «رفع النتيجة لاعتماد الاستشاري».
4. **الاستشاري** (`?as=u-cons`) → «اعتماد النتائج» → ورقة الاختبار والأدلة → اعتماد/رفض بسبب (الرفض يتيح للمقاول طلب إعادة).
5. بعد اعتماد كل المخرجات يكتمل الطلب تلقائياً وتصبح الفاتورة مستحقة؛ الاعتماد التلقائي بعد 48 س وانتهاء مهلة المختبر 12 س ينفّذهما `tick()` كل دقيقة.

> حراس المسارات: الوصول إلى `/admin/*`, `/catalog`, `/approvals`, `/equipment`… خارج صلاحيات الدور يُعاد توجيهه للوحة مع تسجيل حدث «محاولة وصول مرفوضة» في سجل التدقيق. قواعد الأعمال تُجمَّد لكل طلب عند إرساله (`request.rules`) — تعديل الإعدادات يسري على الطلبات الجديدة فقط.
